# Olist Customer Retention & RFM Analysis

An end-to-end e-commerce analytics project using DuckDB SQL, Python, and Power BI to analyse repeat purchasing, customer cohorts, RFM segments, and the relationship between delivery performance and customer reviews.

**Project question:** Which customer segment should an e-commerce business prioritise for retention or re-engagement, and is delivery performance associated with repeat buying?

**Tech stack:** Python, pandas, NumPy, DuckDB, SciPy, statsmodels, matplotlib, SQL, Power BI, Git, GitHub.

## Project Overview

This project analyses the Brazilian E-Commerce Public Dataset by Olist, covering transactions from 2016–2018. It builds an order-level analytical dataset, measures customer retention, segments customers using Recency, Frequency, and Monetary (RFM) analysis, and examines delivery performance alongside reviews and repeat purchasing.

The analysis pipeline includes:
- Data profiling and validation.
- Order-level payment aggregation to prevent revenue double-counting.
- Repeat-customer and second-order purchase metrics.
- Monthly cohort retention analysis.
- RFM customer segmentation and segment prioritisation.
- Delivery-delay and review-score analysis.
- Confidence intervals and statistical comparisons.
- Power BI dashboards and business recommendations.

### RFM Segment to Investigate First

The **New high-value** segment ranked highest under the project's screening heuristic.

- Customers: 14,647
- Share of eligible customers: 15.42%
- Historical revenue: R$4.44 million
- Share of eligible revenue: 28.21%
- Average historical spend per customer: R$303.09

This is a candidate segment for a controlled retention experiment, not a validated prediction of which customers will respond to a campaign.

### Delivery and Customer Reviews

- The 180-day repeat rate was 1.47% among customers whose first eligible order was delivered late, compared with 1.93% among those whose first order was delivered on time or early.
- The estimated difference was -0.45 percentage points, with a 95% confidence interval of approximately -0.82 to 0.00 percentage points and a two-proportion test p-value of 0.051.
- Mean review scores were approximately 2.27 for late deliveries and 4.29 for on-time or early deliveries.

These are observational associations. They do not establish that delivery delays cause customers to stop purchasing.

### Revenue Scenario

The analysis calculates illustrative reactivation scenarios using assumed uplift rates. These are scenario estimates, **not forecasts or proven incremental revenue**. They do not account for contribution margin, campaign costs, customer contactability, or cannibalisation.

## Setup and Reproduction

### Requirements

- Windows with PowerShell, or a compatible Python environment.
- Python version compatible with the dependencies in `requirements.txt`.
- The Olist dataset downloaded from Kaggle.
- Power BI Desktop to explore or modify the dashboard.

### 1. Clone the repository

```bash
git clone https://github.com/rezinak2003-afk/olist-retention-rfm.git
cd olist-retention-rfm
```

### 2. Download the dataset

Download and extract the Olist dataset into `data/raw/`.

At minimum, the core pipeline requires these files:

- `olist_customers_dataset.csv`
- `olist_orders_dataset.csv`
- `olist_order_payments_dataset.csv`
- `olist_order_reviews_dataset.csv`

The full dataset also contains order items, products, sellers, geolocation, and product-category translation files. The pipeline profiles optional files when present.

### 3. Create the Python environment

On Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4. Verify the source files

```powershell
.\.venv\Scripts\python.exe scripts\check_setup.py
```

### 5. Run the analysis

```powershell
.\.venv\Scripts\python.exe scripts\run_analysis.py
```

The pipeline profiles source tables, loads data into a local DuckDB database, creates an order-level analytical dataset, validates order uniqueness, reconciles payment totals, and computes retention, cohort, RFM, delivery/review, confidence-interval, and scenario outputs.

### 6. Run the tests

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/
```

The tests use synthetic data to check analysis logic. They are not a substitute for validating the real dataset outputs.

## Analysis Definitions

- **Customer identity:** `customer_unique_id` is used to represent a person across orders; `customer_id` is order-specific.
- **Eligible orders:** orders with `canceled` and `unavailable` statuses are excluded from retention and RFM analysis.
- **Delivery analysis:** limited to delivered orders with an actual delivery date.
- **Order value:** payment records are aggregated to one row per order before joining, avoiding payment-related revenue fan-out.
- **Review selection:** the latest review answer timestamp is selected per order.
- **Late delivery:** actual delivery calendar date is later than the estimated delivery calendar date.
- **RFM snapshot:** a historical snapshot based on the dataset timeline, not the current date.
- **Repeat customer:** a customer with two or more eligible orders.
- **Meaningful second purchase:** a second eligible order at least 24 hours after the first and within the selected 90- or 180-day window.
- **Cohort retention:** customers are grouped by their first eligible purchase month. Later cohorts have shorter follow-up periods, so retention comparisons must account for right-censoring.
- **Uplift scenarios:** assumed reactivation improvements used to illustrate potential revenue under explicit assumptions, not measured campaign effects.

## Limitations

- The data is historical and covers 2016–2018; it does not represent current live-store performance.
- Olist is one Brazilian marketplace, so findings may not generalise to other markets or businesses.
- Delivery and repeat-purchase relationships are observational and may be confounded by order value, seller, state, category, and customer mix.
- The RFM prioritisation score is a screening heuristic, not a validated propensity model.
- Revenue scenarios exclude campaign costs, contribution margin, contactability, and cannibalisation.
- Statistical significance does not by itself establish business importance or causality.

## Recommended Business Actions

1. Evaluate the New high-value segment as a candidate for a targeted second-purchase campaign.
2. Use a randomised holdout group to estimate incremental 90- and 180-day repeat purchases.
3. Track contribution margin and campaign cost alongside repeat-purchase outcomes.
4. Investigate service recovery for delayed deliveries and measure subsequent customer outcomes separately.
5. Reassess segment size, reachability, and business impact before scaling a campaign.
